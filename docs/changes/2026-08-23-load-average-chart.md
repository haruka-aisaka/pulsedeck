# LoadAverage グラフの追加

## 背景

現状 LoadAverage（システム負荷平均）は取得済みだが、ヘッダーのテキストと CPU ゲージのサブ表示で
「今この瞬間の値」を出しているだけで、時系列の推移が分からない。CPU 使用率だけでは見えにくい
「実行待ち行列の積み上がり（コア数を超えた過負荷）」を時系列で把握できるようにしたい。

## 現状の挙動

- LoadAverage は `/proc/loadavg` から 1分/5分/15分平均を取得済み。
- 表示は 2 箇所のみ:
  - ヘッダーに `0.42 0.55 0.60` のようなテキスト（1/5/15分）。
  - CPU ゲージのサブテキストに `N cores · load 0.42`（1分値のみ）。
- チャート領域（CPU / Memory / Temperature / Network の 4 枚）には Load のグラフはない。
- 履歴データにも Load は蓄積されていないため、レンジ切替（1min/10min/3h/24h）でも遡れない。

## 変更後の挙動

- チャート領域に **「Load Average」グラフを 1 枚追加**する（既存 4 枚と同じカード・同じ描画スタイル）。
  - 追加位置: CPU グラフの直後（CPU と関連が深いため隣に置く）。
- **3 本の折れ線**で 1分・5分・15分平均を表示する。Network グラフと同様に凡例（`1m / 5m / 15m`）を付ける。
  - 色は既存テーマ変数を流用（1分=accent、5分=accent2、15分=warn）。
- **Y 軸は動的レンジ**（表示範囲のデータに追従して上限が変わる。Network グラフと同じ考え方）。
  - ただし過負荷が見えなくならないよう、上限は最低でも「コア数」を確保する （上限 = max(表示範囲のピーク ×
    余白, コア数)）。低負荷時は飽和ラインが枠外へ消えず、 過負荷時はピークに追従して伸びる。
- **「100% 相当ライン（飽和ライン）」を描画**する。load = コア数 の位置に水平の基準線（破線）を引き、 `100%`
  のラベルを添える。これにより Y 軸目盛を読まなくても、線がこの基準線に近い／超えているかで
  「システムが飽和しているか」が一目で分かる。
- 既存 4
  グラフと同じく、レンジ切替（1min/10min/3h/24h）に追従する。長期レンジは平均でダウンサンプリングされる。
- 数値の丸めは軸ラベルの既存ルール（`niceStep` / `fmtAxis`）に従う。

## スコープ外

- ヘッダーのテキスト表示・CPU ゲージのサブテキストは**変更しない**（従来どおり）。
- 新たなゲージ（円形リング）の追加はしない。グラフのみ。
- Load のしきい値による色変化・アラート通知は入れない（飽和ラインの描画のみ）。
- collectors.ts（収集ロジック）は Load を既に取得済みのため変更しない。

## E2E テストチェックリスト

- ### 正常系
  - [ ] ダッシュボードを開くと Load Average グラフが CPU グラフの直後に表示される。
  - [ ] 1分/5分/15分の 3 本の線と凡例が表示される。
  - [ ] Y 軸が表示範囲のデータに追従して動的に変わる。
  - [ ] コア数の位置に「100%」ラベル付きの飽和ライン（破線）が引かれている（例: 4 コア機なら load=4 の位置）。
  - [ ] 低負荷時でも飽和ラインが枠内に見える（Y 軸上限がコア数を下回らない）。
  - [ ] レンジを 1min/10min/3h/24h に切り替えると Load グラフも他グラフと同様に追従する。
  - [ ] ヘッダーの Load テキストと CPU ゲージのサブ表示は従来どおり変わらない。
- ### 異常系
  - [ ] SSE 切断 → 再接続後、Load グラフが履歴込みで復元される。
  - [ ] 過負荷（load > コア数）時、Y 軸がピークに追従して伸び、飽和ラインを超えた分も読める。
- ### エッジケース
  - [ ] 起動直後（履歴が少ない）でもグラフがエラーにならない。
  - [ ] リロード後、history イベントで過去分の Load が描画される。
  - [ ] ライト/ダークテーマ切替で線色・軸色・飽和ラインが追従する。
  - [ ] ウィンドウリサイズで再描画されレイアウトが崩れない。
